# Spring과 호환되는 할 일 쪼개기 API 동작을 정의한다

## 1. 핵심 결정

- `sessionId`는 서버가 저장된 질문·답변과 이전 분해 결과를 찾아 후속 요청을
  이어갈 때 사용한다.
- `proposalId`는 앱과 로그에서 질문 또는 분해 응답이 어느 세션의 결과인지
  식별할 때 사용하며, `sessionId`와 항상 같다.
- `items`의 null 여부로 질문 턴과 분해 턴을 구분한다. `firstStep` 필드는
  언제나 null이다.
- 질문은 대화 전체에서 최대 5회다. 5회 도달 후에는 서버가 분해 턴을
  구조적으로 강제한다.
- 앱은 대화 이력을 관리하지 않고 매 턴 이번 발화 하나만 보낸다 — 대화는 서버
  세션이 보관·복원한다.
- 쪼개기 이어가기는 쪼개기 시작으로 만들어진 세션에서만 동작한다.

## 2. 상세 설계

### 2.1 전체 처리 흐름

```text
[쪼갤 할 일 한 건 지정]
  ↓
[지정한 할 일로 쪼개기 시작 요청]
  ↓
[새 쪼개기 세션 생성]
  ↓
<어떻게 쪼개 달라는 요청이 있는가?>
  ├─ 있음   → (A) 서브 테스크 생성
  └─ 없음   → (B) 추가 정보 판단

(B) <추가 정보가 필요한가?>
  ├─ 아니요 → (A)
  └─ 예     → <사용자에게 추가 질문을 5회나 했는가?>
                ├─ 예     → (A)
                └─ 아니요 → [추가 질문과 선택지 반환]
                               ↓
                             [사용자 답변 전송]
                               ↓
                             [세션에 저장된 대화에 새 답변 추가]
                               └─↺ (B)

(A) [AI가 할 일 1~5개 생성]
      ↓
(C) [대상을 대체할 전체 목록 반환]
      └─ 같은 세션에서 전체 결과를 더 잘게 요청
           ↓
         [AI가 직전 분해 결과를 기준으로 전체 목록 재구성]
           └─↺ (C)
```

### 2.2 시작 요청

`POST /api/v1/ai-sessions/decompose` → `201` (세션을 직접 생성해 반환 — 별도
세션 생성이 필요 없다)

정확한 요청 형식과 제약은 OpenAPI를 따른다. `instruction`이 있으면 추가 질문 없이
바로 분해한다.

### 2.3 이어가기 요청

`POST /api/v1/ai-sessions/{sessionId}/decompose` → `200`

정확한 요청 형식과 제약은 OpenAPI를 따른다. 앱은 선택지 칩 텍스트나 자유 입력으로
이번 턴의 발화 하나만 보낸다.

### 2.4 질문과 분해 응답 구분

정확한 응답 형식은 OpenAPI를 따른다. 질문 턴은 `items`가 null이고 선택지와 질문을
반환하며, 분해 턴은 `options`가 null이고 실행 순서대로 정렬한 `items`를 반환한다.

- **`firstStep` 필드는 유지하되 값은 언제나 null이다.** '지금 할 첫 단계'는
  `items[0]`으로 온다. 분해 턴의 `items`가 비어 있는 모델 응답은 `503`으로
  처리한다.
- 질문 턴의 조건: `assistantText`가 비공백이고 중복 제거 후 `options`가 2개
  이상. 선택지는 최대 4개까지만 내려보낸다.
- 질문은 대화 전체에서 최대 5회다. 질문 턴 5회에 도달하면 이후 응답은 반드시
  분해 턴이다.
- 분해 턴을 받은 뒤에도 같은 세션에 "더 잘게 쪼개줘"를 보내면 서버가 직전
  목록을 기억하고 전체를 더 잘게 재구성해 돌려준다(항목 수 상한 5개 동일).
- "그냥 쪼개줘"·"모르겠어" 같은 발화에는 즉시 분해로 넘어간다.
- 쪼개기 시작 기록이 없는 세션(세션 생성 API로 만든 세션 등)에 이어가기를
  호출하면 `404`다.

`TaskDraft`의 공통 정의와 정규화 규칙은
`docs/specs/spring-compatible-http-base.md`를 따르고, 쪼개기에서는 다음
규칙을 더한다.

| 필드 | 쪼개기 규칙 |
| --- | --- |
| `memo`·`dueDate`·`dueTime`·`reminderMinutesBefore` | **항상 null** |
| `importance`·`estimatedMinutes` | 모델 제안 — 정규화로 null이 될 수 있음 |
| `sourceExcerpt` | **항상 대상 제목** (개행을 공백으로 접고 앞뒤 공백을 없앤 `target.title`) |

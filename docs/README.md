# 문서 안내

`docs/`는 저장소에서 계속 유지할 절차 규약과 기술 스펙을 보관한다.

작업 진행 상태, 담당자와 일정처럼 자주 바뀌는 정보는 GitHub 이슈에서 관리하고
문서에 중복해서 기록하지 않는다.

문서를 작성·수정·삭제할 때는
[문서 작성 및 유지 관리 규약](conventions/documentation.md)을 따른다.

## 디렉터리

| 디렉터리 | 역할 |
| --- | --- |
| `conventions/` | 특정 작업을 수행할 때 반복해서 따라야 하는 절차와 규칙 |
| `specs/` | 코드와 이슈만으로 설명하기 어려운 핵심 결정과 상세 설계 |

## 문서를 둘 위치

여러 작업에서 반복해서 적용할 절차나 판단 기준은 `conventions/`에 둔다.

특정 기능이나 시스템의 계약, 처리 흐름과 핵심 설계 결정은 `specs/`에 둔다.
코드·테스트·OpenAPI·GitHub 이슈만으로 충분히 설명할 수 있다면 별도 문서를
만들지 않는다.

작업 상태, 담당자, 일정, 논의 과정과 단기 작업 계획은 GitHub 이슈나 PR에서
관리한다.

새로운 종류의 문서가 필요하더라도 사용자 확인 없이 `docs/` 아래에 새
디렉터리를 추가하지 않는다.
